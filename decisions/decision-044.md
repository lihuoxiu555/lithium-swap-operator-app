# 决策卡片 #044
- **日期**：2026-09-17 | **阶段**：MVP

## 决策问题
用户可见文案还要不要出现「待接入」？未上线宫格是留死链角标，还是直接不展示？

## 调用的大师视角
- **乔布斯**：未完成的能力不要占宫格。角标「待接入」等于把砍掉的功能摆上货架。
- **俞军**：新体验里写「待接入」会扣价值；替换成本还在，净价值下降。未上线不出现，比出现再解释更干净。
- **张小龙**：不靠「即将上线」刺激点击。一线点进去只为看到一句空话，是无效多巴胺。

## 核心判断
1. 工作台宫格只展示 `status=ready`。placeholder（示例·经营等）不出现。
2. 站点详情拿掉场费电费 / 站点合伙人 / 站点支出三入口。
3. 未上线能力 toast 统一「暂未开放」（扫码 / 证件识别 / 导航 / 轨迹回放）。占位页写「本模块暂未开放」。
4. 注册表仍保留 placeholder 条目，hash 直链可进占位页，不假装已上线。
5. 电柜「二期」标签（`cabP2`）不是「待接入」，本期不动。

## 反方最强论据
decision-017：二期入口藏起来，现场会以为功能被砍。缓解：注册表仍在、直链占位页可解释、PRD 写明不进宫格。失效：若一线必须从 APP 预约场费电费，再给可浏览入口，文案仍禁止「待接入」。

## Non-goals
不删注册表 placeholder；不改电柜「二期」；不改写历史决策卡正文；不改骑手端 / PC。

## 下一步验证
管理员工作台无「示例·经营」、无「待接入」四字。直链 `#/module/demo.ops` 见「暂未开放」。站点详情无场费电费三入口。扫码 / 证件 / 导航 toast 为「暂未开放」。
