# 决策卡片 #041
- **日期**：2026-09-17 | **阶段**：MVP

## 决策问题
站点新增/编辑要不要提供「选择当前位置」，用设备定位当站点坐标？

## 调用的大师视角
- **俞军**：现场价值 = 站在柜边一键落点 − 现在搜门牌或回 PC 填坐标 − 学一个按钮的成本。净价值明显。
- **乔布斯**：只加这一颗按钮。不进页自动定位，不加精度条、海拔、指南针校准。
- **唐·诺曼**：定位必须是明示动作。系统偷偷改坐标，一线会以为表单坏了。

## 核心判断
1. 组织地址下增加「选择当前位置」。点击才取定位。
2. 写入经纬度（WGS-84 转 GCJ-02）、针点、搜索框、详细地址。编辑站不改城市下拉。
3. 拒绝权限 / 超时 / 失败只 toast，不回填。无定位 API 时才用演示坐标并标明。

## 反方最强论据
GPS 偏几十米会把站定到马路对面。缓解：仍可点地图微调，详细地址可改门牌。失效：若运维要求必须精确到柜脚，再接地图 SDK 拖点，而不是先做自动纠偏。

## Non-goals
不进页自动定位；不做真逆地理；不改 PC / 骑手端；不把定位失败自动填成演示坐标（无 API 除外）。

## 下一步验证
编辑浦东站 → 点「选择当前位置」→ 允许则针点离开张杨路；拒绝则坐标不变。无定位环境见陆家嘴环路演示点。
