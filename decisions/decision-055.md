# 决策卡片 #055
- **日期**：2026-09-21 | **阶段**：MVP

## 决策问题
工作台首页要不要在「今日三卡」下增加用户数据 / 电池数据统计？各维度口径怎么定？

## 调用的大师视角
- **俞军**：续费触达、未换电预警、逾期快照是现场运营的高价值信息；电池空闲/使用中是调度刚需。
- **乔布斯**：保留今日三卡看「今天经营」，下面两块看「用户健康 + 资产」；不把 PC 总览整页搬上来。
- **张小龙**：有队列的重叠项（已逾期）必须能点进列表，不能只是死数字。

## 核心判断
1. **保留**今日三卡（换电次数 / 人数 / 套餐收入），其下新增 **用户数据**（9 格）与 **电池数据**（3 格），每行 3 个。
2. **3天内到期**：仅**个人套餐**，`到期日 ∈ (今日, 今日+3]` 且未完结；**不含**渠道人天。
3. **3天未换电**：当前有效用户中最后成功换电 >3 自然日；**不含冻结中**；冻结单独展示 **冻结中**（= 有效个人里 `服务状态=已冻结`）。
4. **总用户（有效）**：展示**总数 + 分项**（个人 · 渠道）；个人含冻结，渠道含待还电。
5. **今日续费** = 已有未完结订单用户今日延长服务期的支付（不含首次开通）。
6. **今日退租** = 今日服务关系完结（按骑手去重）；**今日退电** = 今日完成还电动作（按骑手去重，可未退租）。
7. **已逾期**可点进待办「逾期持电」；电池区块标题可点进设备统计。

## 反方最强论据
首页指标过多，和经营统计 / 待办 / 设备统计重复。缓解：仅做快照 + 关键项可下钻；明细仍在二级页。失效：若运营反馈「首页太长」，再收拢为可折叠。

## Non-goals
不做渠道「3天内到期」；首页不做时间筛；员工不按站点裁这些 Mock 数（同管理员）。

## 下一步验证
登录工作台见三卡 + 用户 3×3 + 电池 1×3；点已逾期进逾期列表；点总用户 / 电池标题进对应模块。

## 知识沉淀
「有效用户」类指标要同时给**总数与分项**；冻结与未换电必须拆开，避免把停服用户算进流失预警。
