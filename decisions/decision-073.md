# decision-073 · 员工管理 + 区域（业务城市）

| 项 | 内容 |
|----|------|
| 状态 | 已采纳（原型 V1.106） |
| 日期 | 2026-11-10 |

## 背景

运营商后台（原型-外卖）已有 **运营员工** 账号：姓名、手机、岗位、功能权限、启用状态。员工出门使用运营商 APP，需能在手机侧维护账号，并按 **业务城市** 划分责任范围。

## 决策

1. **入口**：工作台 · **其他** · **员工管理**（`org.employees`），与 PC「运营商-员工」同源。
2. **权限**：**仅管理员** 可见宫格、新增/编辑；员工账号无入口（与 `finance.account` 同级敏感）。
3. **区域字段（新增）**：
   - **全网**：等同原管理员全网数据范围。
   - **指定城市**：多选自运营商 **已开通业务城市** 列表（Mock：上海 / 杭州 / 溧阳 / 苏州）。
   - 列表与筛选展示「区域」列；表单与 PC 扩展字段对齐。
4. **功能权限**：复用外卖 `EMP_PERMISSIONS` 的 permission id 子集（演示勾选）；正式环境全量同 PC。
5. **数据范围联动**：`[待确认]` 员工登录 APP 后，列表/待办/站点繁忙度是否同时受 **区域城市** 与既有 **siteIds** 约束——原型期仅文案与筛选演示，不改全局 `session.siteIds`。

## 反对理由 / 失效

- 反对：移动端编辑权限风险高；城市与站点双层范围易混淆。
- 失效：若 PC 改为「区域=站点组」而非行政城市，则 APP 枚举改为读 PC 配置。

## 关联

- 原型-外卖：`employeeStore`、`EMP_PERMISSIONS`、员工表单
- 运营商 APP：`prototype/js/employees.js`
