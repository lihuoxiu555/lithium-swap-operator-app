## 1. 结论

先交付**独立手机工作台壳**：登录 → 选身份 → 工作台 / 待办 / 我的，业务能力全部走**模块注册表**插拔。框架期不移植 PC 运营商后台菜单，不假装已上线任何业务模块。

**北极星（框架期）**：评审 3 分钟内走通「登录 → 切角色 → 点已上线模块」；后续接入业务模块时底栏与壳不改。

## 2. 背景与目的

### 2.1 用户问题

运营商管理员与员工日常在站点、路上、车上需要查待办、进运维/审批入口，现网只有 PC 工作台，出门无法干活。

### 2.2 业务目标

- 提供可扩展的 B 端手机入口，与骑手 C 端小程序信息架构隔离。
- 用注册表预留模块槽，业务模块按优先级后续接入，避免一次搬空 PC 菜单。

### 2.3 当前替代方案

回办公室或远程桌面打开 PC 运营商后台（`原型-外卖`）。

### 2.4 为什么是现在

业务模块清单尚未敲定，但壳层 IA / 权限裁剪 / 插拔约定需要先锁，避免后续每加一个模块改导航。

### 2.5 产品判断

| 维度 | 内容 |
|------|------|
| 新体验 | 手机进工作台、看待办、点模块 |
| 旧体验 | 必须回电脑 |
| 替换成本 | 学 3 Tab；框架期几乎无业务学习成本 |
| 净价值 | > 0（框架解决「出门没法干活」的入口问题） |
| 减法 | 框架期塞 PC 菜单会毁认知，一律不做 |

## 3. 用户与假设

| 角色 | 说明 |
|------|------|
| 运营商管理员 | 看经营摘要槽、全量有权模块；底栏待办处理退款/逾期/充值与警告；可切换主体入口（演示单主体可禁用） |
| 运营商员工 | 同一套壳；宫格按 `roles` 裁剪；不显示切换主体 |

**假设**

- `[假设]` 账号体系与现网运营商工作台同一套；演示号可复用 `13800000005` / 密码 `123456`。
- `[假设]` 数据范围枚举：`all` 全网 / `sites` 指定站点；框架期员工可演示「指定站点」。
- `[待确认]` 正式端形态（原生 APP / 企业微信 / 独立 H5）不影响本框架 IA。

**与骑手端关系**：骑手端 = C 端换电；本 APP = B 端干活。禁止抄「首页地图 / 订单 / 我的」。

## 4. 信息架构

```
登录 →（多身份则）选择身份 → 工作台
底栏固定 3 Tab：工作台 | 待办 | 我的
工作台宫格 → 模块页（ready）或统一占位页（placeholder）
待办 Tab → 待办 \| 警告（左右）+ 下方消息列表 → 列表 / 详情
```

待办与警告从工作台挪到底栏 **待办** Tab。消息模块仍在该页，排在待办、警告下面。仍是 3 Tab。

## 5. 模块注册表（插拔唯一接口）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 稳定 ID，如 `demo.ops` |
| `name` | string | 宫格展示名 |
| `group` | enum | `经营` / `运维` / `财务` / `其他`（无「运营」） |
| `icon` | string | 短符号或 emoji |
| `status` | enum | `placeholder` \| `ready` |
| `roles` | string[] | `admin` \| `staff` |
| `badge` | number? | 角标，可选 |
| `route` | string | hash 路由，如 `#/module/demo.ops` |

规则：

1. 宫格**只**由注册表渲染；壳不硬编码业务菜单。
2. 当前角色不在 `roles` → 不展示；直链访问 → toast「无权限」并回工作台。
3. `placeholder` **不进宫格**；hash 直链进统一占位页，文案「本模块暂未开放」。
4. 框架期预置中性名占位槽（示例·经营 / 示例·设备…）仅保留在注册表，**不绑定**现有 PC 模块名，工作台不可见。

## 6. 页面规格

### 6.1 登录

| 项 | 内容 |
|----|------|
| 产品名 | **锂电快换**（登录主标题；Logo 字「锂」） |
| 副标题 | 运营商工作台 · 手机端日常入口 |
| 字段 | 手机号（11 位）、密码、协议勾选 |
| 枚举 | — |
| 空态 | — |
| 错误态 | 手机号空 / 非 11 位；密码空；账号或密码错；未勾选协议 |
| 权限 | 未登录仅可进本页 |
| 成功 | 若账号绑多身份 → 选择身份；否则进工作台 |

演示账号：`13800000005` / `123456`（管理员+员工双身份）；`13900000001` / `123456`（仅员工）。

### 6.2 选择身份

| 项 | 内容 |
|----|------|
| 字段 | 身份卡片：角色名、数据范围摘要 |
| 枚举 | `admin` 管理员 / `staff` 员工 |
| 空态 | 不应出现（无身份则登录失败） |
| 错误态 | — |
| 权限 | 仅登录后、未选定角色前 |

### 6.3 工作台

| 区域 | 字段 / 行为 |
|------|-------------|
| 顶栏 | 仅主体名「锂电快换」；**不展示**角色、数据范围、壳内切身份 |
| 经营摘要槽 | 固定**今日**三卡：**换电次数（次）**、**换电人数（人）**、**套餐收入（元）**。无时间筛。点整区进 **经营统计**。口径见 decision-036 / **037** / **046** |
| 用户数据 | **9 格**，每行 3 个：**今日新增** · **今日续费** · **3天内到期**（仅个人套餐）· **3天未换电**（不含冻结）· **今日退租** · **今日退电** · **已逾期**（点进待办）· **总用户（有效）**（总数 + 个人/渠道分项）· **冻结中**。口径见 decision-055 |
| 电池数据 | **3 格**：**电池总数** · **使用中** · **空闲**。标题点进 **设备统计**。总数 ≈ 使用中 + 空闲 + 离线/维修 |
| 摘要 Mock | 三卡 86 / 18 / 4,690；用户/电池见字段口径 |
| 应用宫格 | 按 `group` 分组（经营 / 运维 / 财务 / 其他）；**仅 `status=ready`**。经营：换电订单、经营统计、设备统计。运维：站点、电柜管理。无「运营」组 |

| 项 | 内容 |
|----|------|
| 空态 | 权限裁空：「暂无可用应用，请联系管理员开通」。摘要为 0 仍展示 0 |
| 错误态 | 列表加载失败条 + 重试（场景台可开关）；摘要不跟宫格失败隐藏 |
| 权限 | 管理员见全部有权模块；员工仅 `roles` 含 staff。摘要三卡管理员与员工同数 |

### 6.4 待办 Tab

| 区域 | 字段 / 行为 |
|------|-------------|
| 入口 | 底栏第二 Tab「待办」；角标 = 待办笔数 + 警告条数 |
| 布局 | 上：左右各半 **待办** \| **警告**；下：**消息**列表（原消息模块） |
| 待办 | **管理员**：退款待审、逾期持电、渠道商充值申请。**员工**：仅逾期持电。空宫格场景为 0 |
| 警告 | **高温**（柜体过温）/ **设备异常**（换电柜离线、未正常弹电池、弹错格口、门禁异常）。管理员+员工可见 |
| 下钻 | 点队列进列表 → 详情；返回回本 Tab，不回工作台 |
| 空态 | 待办：「暂无待办」/ 员工「暂无逾期持电」；警告：「暂无警告」；消息：「暂无消息」 |
| 权限 | 同原工作台规则；员工进退款/充值 toast「无待办权限」 |

### 6.5 消息（待办 Tab 下部）

| 项 | 内容 |
|----|------|
| 入口 | 待办 Tab 在待办/警告卡片下方；「我的 → 系统消息」为次入口 |
| 字段 | 标题、摘要、时间、已读/未读、类型 |
| 枚举 | `system` 系统 / `todo` 待办提醒 / `biz` 业务 |
| 空态 | 「暂无消息」 |
| 错误态 | 加载失败 + 重试 |
| 权限 | 同主体可见；框架期 `todo`/`biz` 可空 |
| 详情 | 从待办 Tab 进入则返回待办 Tab；从我的进入则返回系统消息列表 |

## 7. 核心流程

1. 打开 APP → 登录 →（可选）选身份 → 工作台。
2. 切 Tab：工作台 / 待办 / 我的；埋点 `tab_switch`。
3. 点宫格 → `module_click`（含 `status`）→ ready 页或占位页。
4. 切角色走登录「选择身份」或左侧场景台；工作台顶栏不再切身份。
5. 退出 → 清会话 → 登录页。

## 8. 异常与边界

| 场景 | 处理 |
|------|------|
| 登录失败 | 表单错误文案，不进壳 |
| 无模块权限（直链） | toast「无权限」→ 工作台 |
| 消息空 | 空态插画/文案 |
| 宫格裁空 | 空态「暂无可用应用…」 |
| 弱网/失败 | 错误条 + 重试（Mock） |
| 单主体 | 「切换主体」禁用并说明 |

---

## 9. Non-goals（框架期）

- 不移植 PC 菜单（定价、渠道签约、三台账、融资等）
- 除已点名模块外，不实现其它真实业务（其余仍为 placeholder）
- 换电子流程已落地列表次页；**提交不联真实账务、不改订单状态**；扫码/支付通道 toast「暂未开放」
- 不接真实 API / 推送 / 扫码硬件
- 不改 `原型-外卖` 现有 PC 后台与骑手端原型
- 不做 C 端实名、不做骑手地图换电；**不做运营商侧实名审核**（实名认证由平台处理）
